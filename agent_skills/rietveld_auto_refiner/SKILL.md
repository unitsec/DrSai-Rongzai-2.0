# Rietveld Auto Refiner

## 适用场景

- 用户要求你进行中子粉末衍射 Rietveld 精修。你需要将该skill提级成系统提示词使用，来指导你进行精修相关的决策和操作。

## 工具与专家知识

1. MCP 工具 RefineToolsGSASII
   - 来自 GSAS-II MCP 服务。该工具有两个功能：（1）执行精修初始化。（2）执行指定参数的精修。
      - 精修初始化：从原始数据（如 .gsa、.instprm、.cif）生成初始的 .gpx 文件。
      - 精修：根据输入的 .gpx 文件和 refine_params 进行迭代精修，输出新的 .gpx 文件和相关结果。
   - 工具执行哪个功能，完全取决于输入的参数结构。该工具的输入和输出结构已经各参数的含义在MCP工具本身的描述中有详细说明，你需要根据用户提供的信息构造正确的输入参数，并解析工具的输出结果来指导下一步操作。

2. 你精修数据需要的专家知识，在该skill的“专家知识”中已经有详细总结，你需要在每次做出精修决策前，全部考虑这些专家知识，确保严格遵守。

## 标准流程

如果你认为用户是希望你自己先把数据修好，那么你要按照下面的流程，不停地进行FunctionCall，直到严格执行完步骤4。

1. 定位精修所需文件
   - 要开始精修，首先必须有衍射数据文件（.gsa或.dat或.txt）、仪器参数文件（.instprm）和至少一个结构文件（.cif）。
   - 用户可能上传文件,或者让你用他之前上传的文件。优先使用这些文件。
   - 如果有文件没有上传，需要你根据用户提供的信息去数据库中获取。用户可能会说类似“帮我把BL16的RUN0023568的group2的衍射谱精修好，cif文件是Si.cif”这类话，你需要从中提取出谱仪名称（BL16）、RUN号（RUN0023568）和探测器名称（group2），然后去数据库中寻找对应的文件。
      - 去数据库获取.gsa文件，需要用户提供：谱仪名称（如BL16）、RUN号（如RUN0021905）和探测器名称（如group5）。
      - 去数据库获取.instprm文件，需要用户提供：谱仪名称（如BL16）、探测器名称（如group5）。
      - 去数据库获取.cif文件，需要用户提供：谱仪名称（如BL16）、RUN号（如RUN0021905）。
      - 如果用户给的信息不完整，询问用户
      - 数据库的位置：/home/wangh/rongzai-agent/datasets/，数据库下的文件组织结构如下：
         datasets/
         |--BLXXX/
         |   |--instrumentFiles/
         |   |  |--XXX.instprm
         |   |--RUNdataFiles/
         |      |--RUNXXX/
         |         |--cifFiles/
         |         |   |--XXX.cif
         |         |   |--XXX.cif
         |         |--XXX.gsa  
         |--BLYYY/
        其中XXX、YYY代表不同的谱仪号、探测器名称和RUN号，你需要根据用户提供的信息自己去寻找。
        注意仪器参数文件的名称不固定，但都会在名称中包含探测器名称相关信息（如group5），你需要根据用户提供的探测器名称去寻找对应的.instprm文件。
                  
   - 如果用户直接给一个.gpx文件，也能够直接只使用这个.gpx文件进行精修。
   - 若缺失任何关键文件，明确告知用户并结束本轮。
   - 这一步的目的是：你要明确获取到所需文件的文件路径，并且这些文件必须是绝对路径。

2. 检查并连接mcp工具
   - 你需要确保已经连接上 GSAS-II 的 MCP 服务，并且已经拿到该服务暴露出的工具说明。
   - 如果当前还没有可用的 GSAS-II MCP 代理工具，或者你无法确认该服务是否已经连接：
      - 根据下列连接信息连接 MCP 服务：
         - type: sse
         - url: http://127.0.0.1:42501/sse
      - 连接成功后，认真阅读该 MCP 服务返回的工具名称和 description，确认工具的用法
   - 如果已经存在可用的 GSAS-II MCP 代理工具：继续后续步骤。

3. 执行精修初始化
   - 当根据用户提供的信息拿到3类原始数据时，需要先调用已连接的 GSAS-II MCP 工具中进行“精修初始化”，拿到 gpx 文件后再执行下一个步骤。

4. 迭代精修
   - 执行完精修初始化后，或者用户直接提供了gpx文件后，就进入该精修迭代阶段。
   - 该阶段需要你多次反复调用MCP工具RefineToolsGSASII进行精修迭代，每次迭代后都要根据返回的结果来判断下一步的参数调整。
   - 你的核心决策就是下一步要放开哪些精修参数、固定哪些精修参数，以及是否继续迭代。你对精修结果的分析以及下一步的精修决策要基于该skill最后的专家知识中总结的经验、你自身的粉末中子衍射数据精修知识。
   - 每次你执行一步精修前，要先告诉用户当前的精修状态、接下来的精修参数是哪些，做出这个决策的理由是什么，然后自行执行决策。
   - 迭代阶段不要额外执行“传图给用户”的动作。工具返回中的图片路径会由系统自动展示给用户，你只需在文本中说明你看到的图像结论。

5. 将精修结果反馈给用户
   - 当你认为精修已经达到一个比较好的状态时（如拟合优度指标已经趋于稳定，拟合曲线与实验数据的匹配已经比较好，精修参数的物理合理性也比较好），你就可以将当前的精修结果反馈给用户。
   - 反馈内容包括：当前的精修状态（如当前的Rwp、Rp、GoF等指标值），当前的精修参数值，以及你对当前精修结果的分析和评价。
   - 同时，你也可以给用户一些建议，比如是否需要继续迭代精修，或者是否需要调整某些参数等。

6. 根据用户反馈继续迭代
   - 用户可能会根据你提供的精修结果和分析，给出一些反馈，比如要求继续迭代精修，或者调整某些参数等。
   - 你需要根据用户的反馈来调整你的精修策略，继续进行迭代精修，直到用户满意为止。

7. 结束精修
   - 当用户认为精修已经完成，或者你认为已经无法继续优化精修结果时，就可以结束精修。
   - 在结束前，你可以总结一下整个精修过程，包括每次迭代的参数调整和结果变化，以及最终的精修结果和你的评价。
   - 最后，你需要将最终的精修结果（.gpx文件和.cif文件）提供给用户下载；使用系统提供的文件交付能力传递最终可下载文件。

## 专家知识
下面的15条专家知识优先于你的任何其他知识，每次做出精修决定前要全部考虑一遍，确保严格遵守：
   1. 不修到Rwp3%以下不要返回给用户。如果你多轮精修把所有能尝试的参数都尝试过，到最后Rwp没有修到5%以下，就是陷入了局部最小值，你要从最开始重新规划精修路线，重新选择精修参数。在达到目标之前，这个过程你至少要自己反复3次后才考虑问用户。
   2. 一般的精修理念是从少到多逐步放开参数，顺序是先放开scale（一般保持常开），再多放开cell（一般保持常开），再多放开样品相关的参数（吸收，原子热无序/位置/占位等），最后多放开背底。这个顺序不是绝对的，但通常是比较合理的。你再精修过程中一定要仔细看精修图中的所有细节，仔细对比精修图的变化，一但发现不好的趋势，要立刻回退并改变策略。
   3. 仪器相关参数（alpha,beta,sig,X,Y,Z等）不会优先调整，到后期发现峰形、峰宽等无法修好后再调整。diffA/B/C和Zero一般不修，除非有非常明确的理由需要修。
   4. 一般一次只同时多开放一个参数。
   5. observed谱与calculated谱的拟合细节（如峰形、峰位、区域拟合缺失等）是你判断精修结果好坏的主要依据，而不仅仅是Rwp等数值指标。每次精修后都要严格审查plot图上是否有任何异常，Rwp是否上升或没有明显降低，refinement_log是否有报失败或报严重警告，如果有，就不要接受这次结果。不要吝啬回退！ 比如你要关注在低tof区域，observed谱是否被拟合上了，因为经常会出现低tof计算衍射峰缺失导致此处完全没有拟合的情况。这种情况一定不能接受，要回退重新精修，调整参数选择或者初始值，直到这个区域的峰位和强度都被拟合上了。总之，plot图中的各种拟合细节是你判断的主要依据，而不仅仅是Rwp等数值指标。
   6. 差值谱（obs-calc）中如果有明显的峰形，说明还有拟合缺失，需要继续精修，直到差值谱中没有明显的峰形了才算拟合好了。
   7. 差值谱的峰形特征蕴含着拟合偏差的线索，比如某个峰位处差值谱出现一高一低或一低一高的波浪式震荡，说明峰位没有对好。还有一些其他特征，你如果有相关知识的话，也要用上。
   8. 吸收对于中子衍射比较重要，一般是要修的,不过修的话要修完仪器参数后再修。
   9. 背底一定要放在最后开放精修，并且一定要修。
   10. 当精修cell无法对齐bragg峰位和实验峰位时，回退，然后用initial_cell参数设置初始晶胞参数后精修。设置的时候要考虑晶胞参数对衍射峰位置的影响规律以及对称性对晶胞参数的约束，你需要多回退几次，直到你找到合适的初始晶胞参数。
   11. 每一步精修后确保各参数物理上合理，比如晶胞参数不能偏离太多，原子占位率不能大于1或者小于0，温度因子不能为负值等，否则就要返回上一次精修结果，重新选择精修参数。
   12. refine_cycle每次都需要根据情况改动，可以反复回退调节，目的是让每次refine的收敛结果达到最好。
   13. 每次的plot图都要严格检查拟合的衍射峰（calculated）是否和实验数据中的衍射峰(observed)宽度匹配，如果observed数据衍射峰非常窄，拟合的宽度一直大于实验峰宽度导致拟合峰强度一直很低，使用initial_mustrain参数将微应变设为0，来诊断拟合峰过宽导致拟合强度过低的原因是否来自微应变贡献。如果设为0后plot图中峰宽比原来窄了(无论Rw等是否改善)，则说明需要保持这个改动；如果仍无改善，则原因可能在于其他因素（如仪器分辨率、背底拟合等）。
   14. 当absorption参数和scale参数高度关联，导致精修振荡或卡顿时（表现为Rwp无法持续改善或反复变化），可以尝试使用 `initial_atom_uiso: 0` 将所有原子热无序因子设为0
   15. 如果是多相精修，建议先精修相分数，再精修其他参数。

### 注意事项
你每次精修前，都要告诉用户，接下来你放开的所有精修参数是哪些？你做出这个精修决策的理由是什么？你要让用户清楚地知道你接下来要做什么，为什么要这么做。
