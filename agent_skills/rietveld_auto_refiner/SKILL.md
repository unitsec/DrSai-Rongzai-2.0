# Rietveld Auto Refiner

## 适用场景

- 用户要求你进行中子粉末衍射 Rietveld 精修。
- 在精修过程中，用户的某些指令可能需要你使用此技能才能完成。

## 工具与职责

1. run_bash
   - 用于在工作区内查找输入文件并做路径检查。
   - 典型用途：定位 gsa/instprm/cif 绝对路径、检查文件是否存在。

2. MCP 工具 write_info
   - 来自 GSAS-II MCP 服务（0neutron_gsas_refine.py）。
   - 用于执行一次精修并返回结构化结果。

## 标准流程

1. 定位精修所需文件
   - 要开始精修，首先必须有衍射数据文件（.gsa或.dat或.txt）、仪器参数文件（.instprm）和至少一个结构文件（.cif）。
   - 若缺失任何关键文件，明确告知用户并结束本轮。

0. 自举检查（必须先做）
   - 先检查当前可用工具列表中是否存在 `write_info`。
   - 如果不存在：
     - 使用 `run_write` 或 `run_edit` 将用户 `TOOLS_CONFIG.json` 写入一条 `mcp-sse` 配置（指向 GSAS 服务）。
     - 明确告知用户“已写入工具配置，请发送下一条消息继续”，然后结束本轮。
   - 如果存在：继续后续步骤。

1. 判断输入是否完整
   - 若用户已给出 gsa_path、instprm_path、cif_paths 的绝对路径，直接进入第 3 步。
   - 否则进入第 2 步。

2. 先定位文件
   - 使用 run_bash 在工作区查找 gsa/instprm/cif。
   - 如果缺失任一关键文件：
     - 用一句话说明缺失项。
     - 明确告诉用户下一步需要补充什么。
     - 结束本轮，不要盲目发起精修。
   - 路径齐全后，记录 gsa_path、instprm_path、cif_paths。

3. 执行一轮精修
   - 调用 MCP 工具 write_info。
   - 若返回失败：先解释失败原因，再给出可执行的修复建议。
   - 若返回成功：提取并总结关键结果，再判断是否建议继续下一轮。

4. 迭代策略
    - 每轮只新增少量自由度，禁止一次开放多个高耦合参数。
    - 若结果恶化、出现异常或参数物理意义异常，优先回退到上一轮可用状态。
    - 若指标连续多轮改进不显著，进入暂停态并询问用户是否继续。

## 精修状态语义（用于替代旧架构 require_type）

- `refine_init`:
   - 首次进入任务时执行。
   - 先补齐路径，再进行第一轮初始化精修（通常 `refine_idx=0`，并保持保守参数）。
- `refine`:
   - 常规迭代轮次。
   - 每轮读取上一轮输出（尤其 `gpx_path`、`lst`、`refinement_log`、`plot_path`）并决定下一轮参数。
- `refine_pause`:
   - 当改进趋于饱和、信息不充分、或用户要求暂停时执行。
   - 必须输出当前结果总结和下一轮建议。
- `refine_finish`:
   - 当用户确认结束，或你判断继续收益很小且用户认可时执行。
   - 输出最终结论与参数记录。

## 参数放开顺序（强约束）

1. 先修 `scale`。
2. 再逐步尝试晶胞、仪器参数、吸收、原子参数。
3. `background` 放在后期，避免过早吸收峰型误差。
4. 每轮只增加一个主要自由度。

## 质量门禁

- 每轮必须检查：
   - 指标变化（如 Rwp 是否下降）。
   - `refinement_log` 是否有失败或严重警告。
   - 拟合图中峰位、峰形、强度是否出现明显异常。
- 若任一项异常，不接受本轮结果，给出回退建议。

## 关键参数提示

- `refine_params` 为空通常意味着本轮不会进行实质精修。
- 当峰位持续偏离且普通 cell 精修无效时，可尝试通过 `initial_cell` 给出更合理初值。
- 当峰宽明显过宽且常规参数无效时，可尝试 `initial_mustrain=0` 做诊断。
- 当 `absorption` 与 `scale` 高耦合导致振荡时，可尝试 `initial_atom_uiso=0` 进行隔离诊断。

## 回复模板建议

每轮结果建议按以下结构输出：

1. 本轮输入
   - gpx_path / refine_idx / 关键 refine_params

2. 本轮结果
   - status
   - 关键指标变化
   - 主要告警或异常

3. 决策
   - 是否接受本轮结果
   - 下一轮建议调整参数

## 限制

- 不要捏造文件路径、工具返回值或实验结论。
- 无法确定时优先请求补充信息，而不是编造答案。
- 一次只处理一个探测器数据，避免在同一轮混入多个探测器。
- 若用户提供多个 RUN 或多个探测器，必须先让用户明确单一目标。
- 必须优先使用现有工具间接调用，不要依赖自定义 Python 直连函数工具。

## 自举配置模板（TOOLS_CONFIG.json）

```json
[
   {
      "name": "GSASII_Local_MCP",
      "type": "mcp-sse",
      "config": {
         "url": "http://127.0.0.1:42501/sse",
         "timeout": 20,
         "sse_read_timeout": 300
      }
   }
]
```
